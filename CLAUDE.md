# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

GlyphClock is a web app that displays a custom timezone-free time system. The 24-hour day (1440 minutes from UTC midnight) is divided into 16 blocks of 90 minutes, each with a unique emoji. Each block has 3 sub-periods of 30 minutes, shown by displaying one, two, or three copies of the glyph.

Emoji sequence: 🥐→🦋→🌷→☂️→🌵→🎈→👓→⚓→🦚→🤖→⭐→☁️→🌲→🪁→🪑→♻

## Tech Stack

Hugo static site generator (extended edition, currently v0.164.0), 25 languages
(English + 24 EU languages), each with its own crawlable URL for real per-language
SEO/`hreflang` — see "Why Hugo" below. The interactive app itself (clock, dark mode,
focus text, glyph entrance animations) is still plain vanilla JS/CSS with no
framework or npm dependency; Hugo only handles page generation and translation.

### Why Hugo (migrated from a hand-written multi-page site)

The site used to be hand-written HTML with a client-side `i18n.js` translation
table that swapped visible text via JS depending on `localStorage`/browser
language — every language shared one URL, so Google could only ever index the
English version. Hugo gives every language its own real URL
(`/`, `/de/`, `/fr/`, ...), auto-generates `hreflang` alternates and
per-language sitemaps, and is purpose-built for exactly this multilingual
static-site case (more battle-tested than a hand-rolled generator).

## Local Development

```bash
hugo server -D          # local dev server with drafts, live reload
hugo --minify            # production build, output in ./public (gitignored)
```

No npm/node required to serve the site. `public/` is regenerated by CI on every
push and is not committed.

## Deployment

GitHub Actions (`.github/workflows/hugo.yml`) builds with Hugo and deploys via
`actions/deploy-pages` — **this requires the repo's Settings → Pages → Source
to be set to "GitHub Actions"**, not "Deploy from a branch". Custom domain
`glyphclock.bang-labs.eu` is pinned via `static/CNAME` (copied to `public/CNAME`
on build, same as any other static asset).

To deploy: `git push origin main`. GitHub Pages no longer auto-builds the repo
directly (that only works for plain Jekyll/static content); the Actions
workflow is now the only build step.

## Architecture

```
hugo.toml                     Site config: baseURL, [languages.*] blocks (label, weight, contentDir)
content/<lang>/_index.md      Home page content, one JSON-front-matter file per language
content/<lang>/why.md         "Why GlyphClock Works" page content, per language
content/<lang>/privacy.md     Privacy policy content, per language
content/<lang>/planners.md    Printable-planners download page content, per language
layouts/_default/baseof.html  Shared shell: <head>, .content-layer/.about wrapper, nav, extra_scripts block
layouts/index.html            Home page template (clock, focus feature, extension badges, glyph strip)
layouts/_default/why.html     Why page template (selected via front matter `layout: "why"`)
layouts/_default/privacy.html Privacy page template (front matter `layout: "privacy"`)
layouts/_default/planners.html Planners page template (front matter `layout: "planners"`) — lists downloadable PDFs from static/planners/
layouts/404.html              Standalone 404 (not translated, same for every path)
layouts/_default/sitemap.xml  Custom sitemap override — adds hreflang <xhtml:link> per URL
layouts/partials/head.html    Meta/OG/Twitter/canonical/hreflang/JSON-LD, shared by every page
layouts/partials/nav.html     Logo, dark-mode toggle button, language-switcher link list
static/scripts.js             Client app logic (IIFE): clock, dark mode, nav behavior, focus feature, clock-only fade
static/js/why-citations.js    Why-page-only: wraps cited researcher names in hoverable links to Snippets
static/css/styles.css         All layout/theme CSS, unchanged from the pre-Hugo site
static/glyphclock-widget.js   Embeddable widget for OTHER sites — must stay at this exact path (public embed URL)
static/planners/*.pdf         Printable planner PDFs served for download by the planners page
scripts/migrate-i18n.js       One-time dev tool used during the Hugo migration; not run in production
```

## Key Patterns (cross-file)

**Content is JSON front matter, no markdown body.** Every `content/<lang>/*.md`
file is a JSON object (title/description/heading/body text/etc. as front
matter params) with an empty body — this was a deliberate choice during
migration to carry over existing HTML-with-inline-links content byte-for-byte
via `JSON.stringify` (zero manual escaping risk) rather than converting to
markdown syntax. Templates render these params with `| safeHTML` since they
contain real HTML (`<a href>`, `<li>`, etc.).

**Selecting a page template**: regular content at the language root (why.md,
privacy.md) doesn't get a Hugo "section", so template selection uses an
explicit front matter `layout: "why"` / `"privacy"` field, which Hugo resolves
to `layouts/_default/<layout>.html`. The home page (`_index.md`) doesn't need
this — Hugo resolves it via Kind=home to `layouts/index.html` automatically.

**`contentDir` must be set explicitly per `[languages.*]` block in
`hugo.toml`.** Without it, Hugo doesn't correctly treat `content/<lang>/` as
that language's own content root — regular pages (why/privacy, but not home)
silently got a `/en/` prefix even with `defaultContentLanguageInSubdir = false`
until this was added.

**Home page URLs get a manual `strings.TrimSuffix "index.html"`** in
`head.html`/`nav.html`/`sitemap.xml` — `uglyURLs = true` makes Hugo's raw
`.Permalink` for the home page end in `/index.html` (or `/de/index.html`),
which would make canonical/hreflang/nav links uglier than the pre-Hugo site's
clean `/`. Every other page type doesn't need this.

**`uglyURLs = true`** is what keeps `/why.html`/`/privacy.html` as real
filenames (matching pre-Hugo URLs and existing backlinks) instead of Hugo's
default `/why/index.html`-style pretty URLs.

**Dark mode applies `.dark` on `<html>` (documentElement), not `<body>`**. The
inline `<script>` in `head.html` applies the dark class before first paint to
prevent flash.

**`data-page` attribute on `<body>`** is set from `.Params.layout` (or
hardcoded on 404) — used only for the citation-linkifier and any future
page-specific JS, not for translation (translation is now build-time).

**Clock-only mode**: after 23s of inactivity, non-clock elements in `.about`
fade out via the `.clock-only` class (fades out fully, then collapses layout;
reverses on the way back in — see the sequenced `transition` rules in
`styles.css`). Mouse/touch/scroll restores them and resets the timer.
Submitting a focus text via Enter jumps straight into clock-only mode instead
of waiting out the timer.

**Half-hour interval readout**: tapping the clock (`#currentTime`, or the
embed widget) toggles a text line showing the current 30-min phase as a
wall-clock range **in the viewer's own time zone** (`Intl` conversion from the
UTC phase boundaries), persisted in `localStorage` under `glyphclock-interval`.
Off by default. In the embed widget a plain click toggles it (modified/middle
clicks still follow the backlink). The `interval_hint` tooltip param is
English-only in `content/en/_index.md`; other languages fall back via
`| default` in `layouts/index.html`, same as the hardcoded `title="Test mode"`.

**Adding/editing a translation**: edit the relevant `content/<lang>/*.md`
JSON file directly (or, for a brand-new key across all languages, easiest to
re-derive via `scripts/migrate-i18n.js`'s pattern if a bulk source table
exists — otherwise just hand-edit the JSON per language). No JS translation
table to touch anymore.

**Citation links on the Why page** (`static/js/why-citations.js`) hardcode
researcher surnames (Thompson, Kleitman, Lavie, Ericsson, Zakay, Amabile,
Paivio) and Snippets URLs — this works unmodified across all 25 languages
since proper nouns stay in Latin script in every translation.

**Planner PDFs are pre-built, not generated by CI.** The four PDFs in
`static/planners/` are LaTeX output from the sibling `../Planners/day-planner/`
repo (`day-planner.tex`, `solo-planner-a4.tex`, `solo-planner.tex`,
`3day-planner.tex` — see that repo's `CLAUDE.md`). They're generic/blank
templates (no dates, no names — `\personL`/`\personR` in `day-planner.tex`
are intentionally empty so the shared planner ships with a blank rule instead
of hardcoded names), so a single build serves indefinitely; there's no
per-run regeneration. To update them after editing the `.tex` sources:
`lualatex` isn't installed on this host, so build via Docker
(`docker run --rm --network host -v "$(pwd)":/work -w /work
texlive/texlive:latest bash -c '...'`, install the `emoji` CTAN package into
`~/texmf` first, same steps as `Planners/Makefile`'s `setup`/`planner`
targets) and copy the resulting PDFs into `static/planners/`, overwriting the
old ones. `--network host` matters — the default docker bridge network hit
TLS connection resets fetching from CTAN on this host.
